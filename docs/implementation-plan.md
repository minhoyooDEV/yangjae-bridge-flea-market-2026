# 양재천 브릿지마켓 홈페이지 구현 계획

작성일: 2026-10-03. 현재는 계획 단계이며, 앱 코드 구현이나 DB 마이그레이션 적용은 하지 않았다.

## 1. 목적

계단 아래 1층의 방문객이 QR로 홈페이지를 열고, 올라가기 전에 계단 위 매대와 주요 판매상품을 빠르게 확인한다. 관심 있는 매대를 고른 뒤 실제 위치를 찾아갈 수 있어야 한다.

- 방문객은 로그인 없이 매대·상품 소개와 위치를 본다. 예약·주문·결제는 포함하지 않는다.
- 운영자가 업체를 DB에 직접 등록하고 업체 ID/PW 계정을 사전 생성한다. 업체가 자기 매대 소개·사진을 수정하고 자신의 상품을 등록·수정·삭제한다.
- 상품은 저장 성공 즉시 공개하며, 이후 새 조회에 최신 내용이 표시된다. 이미 열린 방문객 화면의 자동 갱신은 요구하지 않는다.
- 모든 기능은 무료 요금제 범위로 구성한다. 유료 기능 활성화·요금제 변경·유료 체험 시작은 하지 않는다.
- 무료 호스팅 대안으로 변경하는 것은 승인되었다. 기본 배포안은 Cloudflare Pages Free이며 계정 연결과 배포는 대기 중이다.
- 매대는 N개 존재할 수 있으므로 DB에서 동적으로 목록을 구성한다. 새로운 매대 등록은 코드 수정 없이 반영한다.
- 코드와 계획은 GitHub 비공개 저장소로 형상관리한다.

행사 표시명은 제공 사진의 현수막에 보이는 **양재천 브릿지마켓**을 기본안으로 사용한다. 최종 공식 행사명은 별도 확인한다.

## 2. 화면

| 화면 | 최소 구성 |
| --- | --- |
| 방문객 첫 화면 | 계단 위 매대 미리보기 안내, DB에 등록된 N개 매대의 업체명·대표 사진·주요 판매품목이 보이는 한 열 카드 목록, 매대 상세 연결 |
| 매대 상세 | 짧은 업체 소개, 주요 상품 사진·이름·설명, 매대 번호, 계단을 기준으로 찾는 위치 |
| 업체 로그인 | 운영자가 발급한 ID/PW 입력, 로그인 실패 안내 |
| 업체 매대·상품 관리 | 자기 매대 소개·사진 수정, 상품 목록과 등록·수정·삭제, 사진 업로드, 저장 결과 안내 |

휴대폰 화면과 현장 통신을 우선한다. 큰 소개 배너보다 매대 목록을 먼저 보여주고, 사진을 지연 로딩한다. 상품이 없는 매대와 사진이 없는 상품도 안내가 깨지지 않게 표시한다. 별도 운영자 관리 화면은 초기 범위에 포함하지 않는다.

디자인은 **친근하고 따뜻한 분위기**로 확정했다. 모바일 한 열 매대 리스트, `width: 100%`, `max-width: 480px`, 가운데 정렬, 기본 패딩 16px을 적용하고 넓은 데스크톱 화면에서도 같은 폭과 한 열 구성을 유지한다. 480px·16px은 사용자가 숫자를 지정한 값이 아닌 구현 기본 설계값이다. 크림색 바탕·딥그린 본문·주황 포인트, 둥근 카드와 사진 중심 구성을 사용한다.

매대 번호와 표시 순서로 목록을 정렬하고, N이 커지면 페이지 단위로 조회한다. 빈 매대 목록은 준비 중 안내를, 존재하지 않는 매대 상세 주소는 안내와 목록 복귀 링크를 보여준다.

사용자가 HEIC 사진 2장을 제공했다. 시각 확인 결과 홍보 전경은 야간 교각 아래 조명과 시장 전경, 매대01은 전체 매대와 상품 진열 모습이다. 홍보 전경은 현장 소개, 매대01은 해당 매대 소개 사진으로 활용하며 개별 상품 사진과 구분한다. HEIC 원본은 Downloads에 보존했고, EXIF 없이 웹용 JPEG 변환·압축을 완료했다. JPEG 3개는 시각 검증을 통과했다. 실제 화면 적용 후 크롭을 확인한다.

## 4. 권한과 저장 처리

| 주체 | 허용 작업 |
| --- | --- |
| 방문객 | 공개 매대·상품·사진 조회 |
| 업체 계정 | 연결된 자기 매대 소개·사진 수정, 자기 상품과 상품사진 등록·수정·삭제 |
| 운영자 | DB에서 매대 등록·번호·위치·표시 순서·계정 연결 관리, Auth 계정 생성·복구 |

- 회원가입 화면을 생략하는 것과 Auth 신규 가입 차단을 구분한다. 지정 업체만 사용하도록 신규 가입과 익명 계정 생성을 차단한다.
- Supabase 비밀번호 로그인은 이메일 또는 전화번호 기준이다. 업체 ID를 Auth 로그인 식별자로 해석하는 과정은 서버에서 처리하고, 로그인 후에는 업체 자신의 세션을 사용한다.
- 정적 호스팅을 선택할 경우, 이 ID 매핑·로그인 처리를 Supabase Edge Functions의 Free 범위에서 수행하는 방안을 제안한다. 프론트엔드는 정적 파일로 제공하고 매대·상품은 조회 시 Supabase에서 읽으면 DB 변경마다 웹사이트를 다시 배포할 필요가 없다. 아직 확정된 구현 방식은 아니다.
- 공개 테이블에 로그인 이메일·계정 매핑을 함께 넣지 않는다. 비공개 매핑은 공개 API에서 직접 조회하거나 변경할 수 없게 한다.
- RLS는 로그인 여부뿐 아니라 계정과 매대의 연결을 검사한다. 다른 업체의 매대 소개·상품 변경, 다른 매대 ID로 상품 생성·소유권 변경, 다른 업체 사진 덮어쓰기·삭제를 차단한다. 매대 수정은 소개·사진 필드만 업체에 허용하고 매대 번호·위치·표시 순서·계정 연결 변경은 업체의 DB 권한에서 제외한다.
- 공개 Storage 버킷의 사진은 URL을 아는 누구나 볼 수 있다. 공개용 사진만 저장하고 업로드·변경·삭제에 업체별 권한을 적용한다.
- 사진 검증·업로드와 상품 저장이 성공한 뒤 완료를 안내한다. 실패하면 입력 내용과 이전 공개 사진을 유지한다. 사진 교체 시 새 경로를 사용하고 DB 변경 성공 후 이전 파일을 정리한다.
- 프로젝트 URL·Publishable key와 서버 전용 Secret key를 구분한다. 비밀 키는 브라우저·로그·Git에 포함하지 않고, 개발·미리보기·운영 환경의 적용 대상을 명시한다.
- 정적 프론트엔드와 Edge Functions 조합에서는 Secret key를 Supabase 함수의 서버 환경에만 둔다. 브라우저에 내려가는 정적 파일이나 빌드 시 치환되는 공개 환경변수에 포함하지 않는다.
- 저장 후 새 조회가 최신 상품을 읽도록 데이터 캐시를 설정한다. 캐시를 사용한다면 저장 시 관련 목록·상세 캐시를 갱신한다. 열린 화면의 자동 갱신을 위한 Realtime은 초기 범위에 추가하지 않는다.

## 5. 무료 운영 예산

다음 수치는 2026-10-03 공식 Supabase Free 문서 기준이다. 지정 프로젝트의 CLI 인증과 로컬 `init/link`를 완료했고 대시보드에서 **Free·Healthy·Nano·Tokyo**를 확인했다. 현재 사용량과 기존 테이블·권한 구성은 별도로 확인해야 한다.

| 항목 | Free 기준 | 운영 방침 |
| --- | --- | --- |
| DB | 프로젝트당 500 MB | 업체·상품 텍스트와 사진 경로만 저장 |
| 파일 Storage | 1 GB | 업로드 전 압축, 교체·삭제 후 불필요한 파일 정리 |
| 일반 Egress | 청구 주기당 5 GB | 필요한 필드·상품만 조회하고 과도한 반복 요청 방지 |

| Edge Functions | 월 500,000회 호출 포함 | 정적 호스팅 선택 시 업체 ID 매핑·로그인에 사용하는 방안 검토 |
| 프로젝트 정지 | 약 7일간 비활동·낮은 활동 시 일시정지 가능 | 행사 전 상태 확인, 필요하면 대시보드에서 재개 |
| 자동 백업 | Free에 미포함 | 업체·상품 데이터와 사진 수동 백업 |

사진은 **상품당 대표사진 1장, 200 KB 안팎 목표, 최종 업로드 파일 1 MB 이하**를 제안한다. 이는 서비스 한도가 아닌 미확정 설계값이다. 무료 전송량 5 GB 두 항목을 자유롭게 합쳐 쓰는 10 GB로 계산하지 않는다. 업체 수·상품 수·예상 방문량이 정해지면 기존 조직 사용량을 포함해 여유를 산정한다.

Vercel 프로젝트 `yangjae-bridge-flea-market-2026`의 로컬 연결은 완료했고, 연결된 팀이 Hobby임을 확인했다. Vercel은 Hobby를 개인의 비상업적 이용으로 제한하고 상품 판매 홍보를 상업적 이용 예시로 명시하므로, **사용자 승인에 따라 실제 운영 호스팅은 무료 대안으로 변경한다**. Vercel 유료 전환은 하지 않는다. 기존 연결 완료를 배포 완료로 해석하지 않는다.

기본 배포안은 **Cloudflare Pages Free**로 채택한다. 계정·프로젝트 연결과 배포는 아직 실행하지 않았다. Functions를 거치지 않는 정적 파일 요청은 Free에서도 무료·무제한이며 월 500회 빌드를 제공한다. 기업·조직 이용을 전제로 한 일반 약관과 Developer Platform 약관에서 개인의 비상업적 이용으로만 제한하는 조항은 확인하지 못했으며, 정적 파일 제공 한도와 함께 선정 근거로 사용한다. Supabase의 DB·사진 전송량 한도는 별도로 적용된다. Netlify Free도 공식적으로 상업적 이용을 허용하는 대안으로 확인했다.

## 6. 구현 단계

1. 로컬 Git 초기화와 [GitHub 비공개 저장소](https://github.com/minhoyooDEV/yangjae-bridge-flea-market-2026) 생성·`origin` 연결을 완료했다. 계획과 이후 코드를 이 저장소로 관리하며 비밀 값과 로컬 연결·환경변수 파일을 제외한다.
2. Free·Healthy 상태를 확인한 Supabase 프로젝트 `sgxnccckhweykhautotb`의 CLI 인증·로컬 `init/link`·공개키 인증 확인을 완료했다. 기존 테이블·권한·사용량을 확인하고 Cloudflare Pages Free 연결을 준비한다. 정적 프론트엔드와 Supabase Edge Functions 조합을 우선 검토한다.
3. 모바일 한 열의 매대 목록·상세·업체 관리 화면을 로컬에서 구현한다. DB의 N개 매대를 정렬·페이지 조회하고 확정된 행사 정보와 배치를 반영한다. 준비된 웹용 JPEG를 적용하고 실제 화면에서 크롭을 확인한다.
4. Auth, 비공개 계정 매핑, 매대·상품 테이블, Storage와 RLS를 구현하고 운영자용 계정 발급 절차를 문서화한다.
5. 실제 저장·공개·권한·사진 교체를 검증한다. 무료 호스팅 기본 주소로 배포와 모바일 확인을 마친 뒤, 그 주소를 여는 인쇄용 QR 이미지를 만든다.

## 7. 의미 있는 검증

연동 준비 단계에서는 `.env.local`에 프로젝트 URL과 `sb_publishable` 공개키를 값 출력 없이 저장했고, `/auth/v1/settings`가 정상 키에 HTTP 200, 잘못된 키에 HTTP 401을 반환하는 것을 확인했다. `/rest/v1/` 루트의 HTTP 401은 Secret key를 요구하는 정상 정책 응답이므로 테이블 조회 검증으로 사용하지 않는다. 앱·DB 마이그레이션·RLS·업체 로그인은 아직 구현하지 않았으며, 아래는 이후 기능 완료 조건이다.

`supabase/config.toml`은 로컬 개발용 설정이다. 신규 가입·이메일 가입·익명 로그인을 차단하는 설정을 준비했으며, 원격 프로젝트의 Auth 설정에는 아직 적용하지 않았다.

- 실제 휴대폰으로 1층 QR을 스캔해 로그인 없이 매대 목록을 열고, 관심 상품에서 매대 위치까지 확인한다.
- DB에서 매대 추가·순서 변경 후 코드 수정이나 재배포 없이 새 조회에 반영된다. 빈 목록·존재하지 않는 매대와 많은 매대의 페이지 조회를 확인한다. 넓은 화면에서도 가운데 고정 폭과 한 열 구성을 유지한다.
- 업체 A는 자기 매대 소개·사진과 상품을 관리할 수 있고 업체 B의 소개·상품·사진은 ID나 파일 경로를 직접 바꿔 요청해도 변경하지 못한다. 자기 매대라도 번호·위치·표시 순서·계정 연결 변경은 거부한다. 로그아웃 상태에서는 모든 변경 요청을 거부한다.
- 공개 API 응답과 배포된 브라우저 파일에 계정 매핑·로그인 이메일·Secret key가 노출되지 않는다.
- 업체 저장 성공 후 별도 방문객 세션의 새 조회에 최신 매대 소개·상품·교체된 사진이 보인다. 삭제한 상품은 공개 목록에서 사라진다.
- 잘못된 파일 형식·크기 초과·네트워크 실패를 처리하고, 실패 시 입력 내용과 이전 공개 정보를 유지한다. 사진 교체·상품 삭제 뒤 불필요한 파일이 정리된다.
- 배포 전 실제 요금제·사용량·활성화 기능을 확인한다. 무료 한도가 부족하면 사진·조회량을 조정하며 유료 전환을 실행하지 않는다.
